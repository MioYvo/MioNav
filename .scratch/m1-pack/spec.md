# M1 · 离线地图包可达

Status: ready-for-agent
Type: spec
Feature: m1-pack
Sources: `HANDOFF.md` §7 的 M1、`docs/design.md` §12 与 §14.4

## Problem Statement

手表上的 HUD 现在只有转向卡、路线和一条空白的底图。`HudActivity` 会尝试打开 `filesDir/tiles.mbtiles`，但没有任何途径把文件放进去：`adb push` 到应用私有目录需要 root 或 debuggable 构建，普通用户根本做不到。于是「底图」这个核心卖点在实际使用里等于不存在——隧道里、山区里、手机没电时，手表什么都画不出来。

对骑手来说，问题可以这样描述：**我给手表装不了地图，所以它离了手机就只是一块显示转向牌的屏幕。**

## Solution

手机变成一个只读文件服务器，手表通过局域网（热点或同一 Wi-Fi）把离线包拉到自己本地，校验通过后才替换旧包。包由一条命令从 OSM 数据生成。

装好之后：手表的底图来自自己的存储，关掉蓝牙、手机没电、进隧道，路网照画不误。手机只负责导航数据。

手机的 HTTP 服务**按需启动**：手表先在 BLE 上报告自己装了哪个版本的包，手机比对后只在确实过期时才开服务。版本一致时，8080 端口根本不会打开。

对骑手来说，操作只剩两步：手机导入一个包 → 手表点一下同步。其余判断都由两端自己完成。

## User Stories

1. 作为骑手，我想在手表上装一次离线底图，这样隧道里和山区里也能看见路网。
2. 作为骑手，我想在手机上导入一个 `.mbtiles` 文件，这样不用连电脑就能换区域。
3. 作为骑手，我想让手表自己判断包是否过期，这样我不必记住版本号。
4. 作为骑手，我想让手机只在确实要更新时才开服务，这样平时不白白耗电、也不留一个开着的端口。
5. 作为骑手，我想在版本已经一致时手表直接告诉我「已是最新」，这样不用等一个永远不开始的下载。
6. 作为骑手，我想在同步完成后手机自己把服务关掉，这样我不用记得回头关。
7. 作为骑手，我想在下载中断后接着下载，这样 100 MB 的包不必从头再来。
8. 作为骑手，我想在校验失败时保留旧包，这样坏文件不会毁掉一份能用的底图。
9. 作为骑手，我想在下载期间继续看旧的底图，这样导航不中断。
10. 作为骑手，我想在手表上看到下载进度，这样我知道还要等多久。
11. 作为骑手，我想只用手机热点就能传包，这样出门在外不需要电脑。
12. 作为骑手，我想在存储不足时收到明确提示，这样不会写出半个文件。
13. 作为骑手，我想看到当前包的名称、版本和大小，这样知道该更新哪个区域。
14. 作为骑手，我想关掉蓝牙后底图依然存在，这样手机没电也不影响看路。
15. 作为骑手，我想在手表还没装包时照常导航，这样新机不至于白屏。
16. 作为骑手，我想在手机上手动开启共享底图，这样不连手表也能把包给别的设备。
17. 作为维护者，我想用一条命令从 OSM 抽出某省或某个 200 km 走廊，这样出包没有手工步骤。
18. 作为维护者，我想出包时自动生成 manifest（bbox、zoom、瓦片数、字节数、sha256），这样两端都能校验同一份事实。
19. 作为维护者，我想用脚本的自检模式核对 manifest 与文件一致，这样发布前能拦住错包。
20. 作为维护者，我想服务端只暴露三个端点且不做目录列举，这样攻击面最小。
21. 作为维护者，我想下载器能在纯 JVM 上跑通，这样回归测试不需要真机。
22. 作为维护者，我想让手表忽略服务端的坏字节并回滚，这样一次坏传输不会留下坏状态。
23. 作为维护者，我想让包格式保持 SQLite，这样局部更新可以用一句 `INSERT OR REPLACE`。

## Implementation Decisions

**新模块 `core/pack`（纯 JVM，零运行时依赖）**
放四样东西：`PackIdentity`（id、version、bytes、sha256、tiles）、`PackServer`（只读 HTTP）、`PackClient`（同步）、`PackVerifier`（算 sha256 与字节数）。这样两端在同一模块，测试可以在一个 JVM 里让它们对打。

**HTTP 契约（三个端点，就三条）**
- `GET /manifest.json` — 原样返回包目录里的 manifest 文件。
- `HEAD /pack.mbtiles` — 带 `Content-Length` 与 `X-Mionav-{Pack,Version,Sha256,Tiles}`，`Accept-Ranges: bytes`。
- `GET /pack.mbtiles` — 全量 200，或带 `Range: bytes=N-` 时 206 + `Content-Range`。
- 其余路径、目录穿越、多区间 Range：404 或退回全量 200，不做目录列举，不做多区间。

**手表不解析 JSON**
manifest 只在磁盘和 `GET /manifest.json` 里存在。手表需要的四个数从 HEAD 的头里拿。这样 `core/pack` 不需要引入 JSON 库，`android/pack` 里现成的 `PackManifest` 继续用 `org.json`，只在手机侧把 manifest 转成 `PackIdentity`。

**同步算法（可续传、可回滚）**
1. HEAD 取远端 identity。
2. 与本地 sidecar 记录的 identity 比较；四个字段全等则返回 `UpToDate`，不发 GET。
3. 否则写到 `<dest>.part`。若 `.part` 已存在且 `.part.identity` 记录的 sha256 与远端一致，用 `Range: bytes=<已有长度>-` 续传；不一致就丢弃重来。
4. 全部字节到手后校验 sha256 与总长度。
5. 通过则 fsync、原子改名覆盖目标文件、写 sidecar；不通过则删掉 `.part`，目标文件与 sidecar 一律不动，返回失败原因。

**服务端实现选择**
手写 `ServerSocket`，不用 Ktor。理由：只有三条路由，加一个大依赖不划算；而且纯 JVM 才能在测试里直接起。一次一个连接、`Connection: close`，够一台手表用。

**端口不是契约**。服务端先试 8080（方便用笔记本直接把包拉下来调试），占用就退到系统临时端口（`bind(0)`，不是自选随机数）。真正生效的端口总是出现在 HELLO 的 URL 里，手表从不猜端口。

**包目录与导入**
手机上一个包一个目录，含 `region.mbtiles` 与 `manifest.json`，与 `docs/design.md` §12.5 一致。导入走系统文件选择器（SAF），不需要存储权限。导入时若没有 manifest，就用 `PackVerifier` 现场算 sha256、字节数，再用 `TileStore` 数瓦片数，补写一份 manifest——这样「只给一个 .mbtiles」也能用。

**先问版本，再开服务**
HELLO 帧的载荷现在只被 ACK，没人读。M1 把它变成双向的能力交换，两个方向载荷不同：

- 手表 → 手机：`helloVersion`、`hasPack` 标志、`packId`、`packVersion`、`packBytes`。没装包时后三项为空。
- 手机 → 手表：`helloVersion`、`urlLen`、`url`。`urlLen = 0` 表示「你的包是最新的」。

手机收到手表的 HELLO 后，拿 `(packId, packVersion, packBytes)` 与本地要分发的包比对：

- 一致 → 回空 url，**HTTP 服务不启动**，连接继续只跑 NAV。
- 不一致 → 启动服务端，回带 `http://<手机IP>:<实际端口>` 的 HELLO。

服务端生命周期：

- 只在两种情况启动：握手判定需要更新，或用户在手机界面手动点「共享底图」。
- 手表下载校验通过后，用新的 identity 再发一次 HELLO；手机看到一致就停服务。
- 兜底：10 分钟没有任何 HTTP 请求自动停；蓝牙断连超过 60 秒且传输未完成也停。
- 端口：先试 8080，占用则退到系统临时端口；两种情况下 URL 都带实际端口。用临时端口时手机界面仍会显示完整 URL，方便手工验证。
- url 的主机部分取手机当前的 Wi-Fi 或热点接口地址（热点通常是 `192.168.43.1`）；没有任何局域网地址时回空 url，界面提示「先开热点或连 Wi-Fi」。

判定逻辑是一个纯函数（本地 identity，远端 identity）→ UpToDate / Serve，放在 `core/pack` 里，可以单测。`docs/protocol.md` 要同步补这一节。

**权限与明文 HTTP**
手表现在没有 `INTERNET` 权限，且 Android 9 起默认禁明文。手表只需要连局域网，所以加 `INTERNET` 并开 `usesCleartextTraffic`，在 spec 之外用一行注释说明这是一次有意让步。

**出包脚本不做图层裁剪**
`tools/build-pack.sh` 用 planetiler 内置 `openmaptiles` profile，输入 `--pbf`、`--bbox`、`--zoom`，输出 `.mbtiles` 并生成 manifest。自定 profile 只留六类道路与水面的方案留到后面，代价是体积多 40–60%（`docs/design.md` §12.3 的实测锚点）。首轮实测用马恩岛级别的小区域，不下载 1.6 GB 全国 pbf。

**验收**
手表装好包后关掉手机蓝牙，`TileSceneBuilder` 仍能画出 450 m 半径的路网。

## Testing Decisions

**好测试的标准**：只断言外部行为——磁盘上有什么文件、HTTP 回了什么、函数返回什么；不断言内部类的调用顺序或私有状态。不 mock HTTP，让真实的 socket 说话。

**只有一条缝隙**：`core/pack` 的 JVM 测试。测试在临时目录里放任意字节（不要求是真 SQLite，服务端只搬字节），起服务、跑同步、比对文件。`./gradlew test` 保持不需要 Android SDK。

**要覆盖的行为**
1. HEAD 返回长度与四个 identity 头。
2. 全量 GET 的字节与源文件逐字节一致。
3. `Range: bytes=N-` 返回 206，内容正好是后缀。
4. 首次同步：无本地文件 → 下载 → 校验 → 目标文件出现，`.part` 消失。
5. 续传：`.part` 已有一半 → 只请求后半段（用服务端收到的请求行断言）。
6. 校验失败：服务端内容被改过 → 返回失败，目标文件与 sidecar 不变。
7. 已是最新：identity 相同 → 返回 `UpToDate`，且没有任何 GET。
8. 未知路径与目录穿越一律 404。
9. 握手判定：两端 identity 一致 → 判定 UpToDate，服务端从未绑定端口；不一致 → 判定 Serve。
10. 空闲退出：服务端在配置的空闲窗口到期后停止监听，端口可以立刻被重新绑定。
11. 端口回退：首选端口已被占用时，服务端改绑临时端口，暴露的 URL 里是实际端口；首选端口空闲时就用它。
12. 回归：服务端 `stop()` 后可以再次 `start()`，端口不泄漏。

**先例**：`core/proto` 的 `ProtocolTest` 就是这种写法——真实字节进、真实对象出，无 mock。

**不进缝隙的部分**：手机起服务与 SAF 导入、手表启动时调同步、HUD 上的进度文字。这些只有 Android API，逻辑已经下沉到 `core/pack`，由 M2 的真机烟测覆盖。

## Out of Scope

- 自定 planetiler profile 与图层裁剪。
- 增量 patch 包（`docs/design.md` §12.6），M1 只做整包传输。
- 多包管理与按区域切换；M1 一个包。
- 用 BLE 传大文件。
- 自动发现手机地址（mDNS、二维码、手工输入）。
- 真机验证与真实 OSM 数据的容量校准（属 M2）。
- 夜间主题自动切换。

## Further Notes

- 首轮实测基准取 `docs/design.md` §12.2 的马恩岛：8078 块瓦片、6.0 MB、z14 平均 633 B。偏差超过 15% 再回头谈裁剪。
- 服务端只面向局域网，但仍然监听 `0.0.0.0`；防火墙与热点本身是边界，spec 不引入鉴权。
- 三个数字（`appVersion`、`protocolVersion`、`dataSchemaVersion`）在每次发布时一起记录，见 §13。
- 手表侧的 HUD 进度只做一行文字，不做进度条动画。
- 8080 只是「方便调试」的偏好，不是协议的一部分；任何测试或客户端都不得假定端口。
- 按需启动服务是省电与减小攻击面的手段，不是安全边界：同一局域网内的任何设备在服务打开期间都能拉到包。
- 握手失败（手表没收到 HELLO、或手机不认这个 `helloVersion`）时手表不发请求，界面显示「未确认版本」，用户可手动触发一次同步。
